# Code audit, 2026-11-18

Scope: the whole DLL (`src/`, about 64,000 lines: 8 times the code of the [2026-10-25 audit](audit-2026-10-25.md)) and the GSC
modules (`content/scripts/maps/`, 17,000 lines; the QA modules only for "does anything run in normal play"). Method: eight readers in
parallel, one per part (native.c; the console; menus, texts and fonts; the native Direct3D 11 / 12 renderers; the upscalers and the
Direct3D 9 capture; network, saves and settings; engine glue and input; GSC), each asked for bugs, leaks and per-frame costs with a
file, a line and a failure scenario. Every finding below was then read again in the code before it was fixed or listed. Nothing was
profiled and nothing was run in the game for this audit: performance remarks are from reading.

What was checked after the fixes: both DLLs build (64-bit and 32-bit, no new warnings), `tools/test_netguard.sh` (38 cases, 11 new;
the new ones fail on the old `netguard.c`, 10 of 11), `tools/test_inimerge.sh`, `tools/test_menutable.sh`, `tools/test_addr.sh`
(builds), `tools/check_gsc.py`, `tools/check_raw_addresses.py`, `tools/pr_checks.py`.

QA runs in the game (test copies, the same evening; the QA scripts now set `MW2COOP_NOUPNP`, so no run changed the router):
- network pairs on the Trainer, `bay`: 64-bit, 32-bit and iw4x-sp, 5 of 5 PASS each; the host learns its partner, the guard drops
  nothing of a real session, no script error. `restart` (64-bit): both PCs get the same decision ("load", logged once though sent three
  times) and load the same checkpoint; its first check fails because it still expects the mod's start point `timed_ads`, while a failed
  mission has loaded the game's own checkpoint since 2026-11-17 (here the one at the level's start): the scenario's expectation is old,
  this path was not changed.
- split screen (mode 11) on the native Direct3D 11 and 12 renderers, and on Direct3D 12 with FSR 3 at 1280x720 (context, depth and motion
  passes, dispatch OK): no crash, 0 refused draws, no scene picture written (the old ones in `mw2coop\native11` kept their dates). One
  of the two FSR runs had a script error inside the game's own `trainer.gsc` (`setObjectiveState`, an assert under `devmap`); the other
  run and a run of a control DLL (the last commit plus the UPnP switch only) had none: not reproduced, most likely the timing of a first
  run with cold shader caches.
- iw4x-sp, five levels in one process (Trainer, Team Player, Cliffhanger, No Russian, Takedown): the script table passed 400 entries at
  No Russian (the old table ended at 320), and `airport.gsc` and `favela.gsc` loaded with all their patches (15/15, 17/17); no script
  error. This is glue F1 seen in the game.
- a split screen lobby left by `stopListening` (as the lobby's leave popup does): 3 s later the log says it was left, and a level after it
  has no script error. (Left without the popup's `specialops 0`, the next Trainer got the Spec Ops loadout: the test's doing, not the mod's.)

Not run: the Museum choice over the network, the password limit, the packet guard against forged packets on the wire (the unit test
covers it), the console fixes, a resolution change or Alt+Enter.

Severity: **H** high (a crash, lost data or broken co-op in normal play), **M** medium (real, needs a condition), **L** low.

## Not fixed: for the owner to choose (each needs a game run, or is a design question)

Renderers and upscalers:
- **DX F1 (H)** `natdraw12.c`: the Direct3D 12 pipeline cache is keyed by the raw addresses of the shader and declaration objects and is
  never emptied. After a level change a new shader at a freed address can get the old level's pipeline (wrong materials), and pipelines
  pile up for the session. Fix: a 64-bit id per shader / declaration as the key, and the pipelines of a destroyed shader released
  through the fenced garbage list. Needs a level-chain run on DX12.
- **DX F3 (M)** `nat12.c nat_image_download`: reading a texture back (the logo and pad icons at the main menu) records into the render
  thread's command list from the main thread and flushes it. Fix: its own allocator and list, or a request the render thread runs.
- **DX F2 (M)** `natdraw12.c alloc_const`: a flush when the frame's constants segment is full leaves the draw being made without its
  targets and tables in the new list (very heavy frames only).
- **DX F5 (M-L)** the copy queue overwrites textures the frames in flight still sample (model lighting volume, film planes).
- **U1 (M)** the upscalers are sized once: after a resolution change in the menu, FSR 3 / DLSS stay off for the session (bilinear
  stretch), and the negative LOD bias stays after a switch back to the output size.
- Perf (from reading, not measured): DX F6 split screen on DX12 waits for the GPU each engine frame; DX F7 static vertex and index
  buffers in upload heaps; DX F8 Direct3D 11 uploads 8 KB of constants and rebinds everything each draw; DX F10 the shader warm-up
  translates every shader again each level. U9: the D3D9 capture thread polls for 120 s on the native renderers.
- 9on12 path only (not the default): U2 no fallback when the upscaler cannot run, U5 back buffer barriers, U8 a queue per
  Direct3DCreate9, U10 a copy with refinement off. U4: the cursor scale stays after switching to the output size.

native.c:
- **1 (M)** the swap chain Present hook hands a stale (32-bit) or NULL (64-bit) device to the console / FSR / shots after a vid_restart.
- **2 (M)** an engine error inside a mode-11 block longjmps past the restore of the screen-update busy flag and the view rectangle.
- **3 / 4 (M)** after a vid_restart the vtable bookkeeping can forget a hook of ours under another one (a Reset loop is possible), and
  the 64-bit Present hooks are not put back outside split screen (the console stops drawing).
- **5 (M-L)** on a build whose addresses moved, `body_dobj_sync` and `aim_assist` can call a function that was not found and use what
  it returned.
- 7 a false "HANG" log and thread walk 10 s into the first level after a split session; 8 the coop dvar thread's stop relies on a
  60 ms sleep; 10 a QA fake-pad file is opened every 250 ms; 12 QA-only log lines can overflow their buffers.

Console: C1 (M) on 64-bit the console's raw mouse runs on the raw-input thread and takes background clicks; C2 (M) its cached
state block is held across a device Reset (possibly part of Vlad's vid_restart / Alt+Enter crash); C4 a very costly repaint with the
completion list open; C5 Ctrl+L / Clear Output come back after a resize; C7, C8 pointer mode and scrollbar; C10 the selection shifts
when the buffer is full; C11 the render thread reads pinned string dvars; C12 replaceable texts used as printf formats.

Menus: F2 (M-H) the Enhanced page builds and registers menus from the control thread (the game's main thread can rebuild the list at
the same time); F5 (M) pointers into the UI zone are kept across its reloads; F7 the device thread runs `update_texts`; F8 menu copies
are made again at each rebuild and never freed; F9 every menu tick scans the menu list about 27 times; F10 texts from the `.str` files
are used as printf formats.

Network: ACC-1 (M) "Steam friends only" and the password trust the Steam ID written in the packet (a known friend's ID passes);
UPNP-1 (L-M) a permanent port forward (routers that refuse a lease) stays when the game quits; PRG-2 save lookups read the save files
about N²/2 times on the main thread.

Glue: F3 (M) the caches of transplanted models are never cleared at a level change; F4 the 32-bit string-release guard keeps its
verdict in a global between two instructions; F7 the load profiler (QA) looks up modules while a thread is suspended; F8 the voice fix
can copy hundreds of MB inside DllMain on a drive without hard links; F9 a 32-bit stub's overhead before the server step hook;
F10 the SDL pad thread wakes 250 times a second; F11 a sound pool block is orphaned at each vid_restart.

GSC: F1 the rest: the checkpoint dvars are not reset when a new session starts, so a host that played earlier in the same process
restores what the client does not; F3 after the ending's credits both players stay in the Museum with no way on; F4 the leash always
moves player 2 to player 1, also when player 2 leads; F5 a restart can pull an ally out of a vehicle; F7 Gulag's evac scans every
script model ten times a second.

The 2026-10-25 audit's items left by the owner's choice (L2, L3, L4, N2, N3) are not repeated.
